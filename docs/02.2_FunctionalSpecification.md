> **Язык UI:** русский. Технические коды (HTTP, exception) пользователю **не показываются**.

## Как пользоваться этим документом

| Роль | Что брать из документа |
|------|------------------------|
| Product / Design | Экраны, тексты, состояния, переходы |

- **As-is** — так уже работает текущий Android-клиент (ориентир реализации).

## 1. Продукт и принципы

### 1.1 Что это

StreamPass — сервис **умной маршрутизации** трафика (ускоритель):  
зарубежные сервисы идут через защищённый relay, российские — напрямую.  
Пользователь нажимает **одну кнопку**; остальное делает система.

### 1.2 Что говорить и чего не говорить

| Запрещено в UI/маркетинге | Правильно |
|---------------------------|-----------|
| «Ускорение интернета» | «Стабильный доступ к зарубежным сервисам» |
| «Мы видим ваши сайты» | «Собираем только технические параметры соединения» |
| «VPN» как обещание full-tunnel | «Умная маршрутизация» / «ускоритель» |

Внутри Android технически используется VPN-профиль ОС — это **не** значит full-tunnel для всего трафика (см. DIRECT vs bypass).

### 1.3 Роли доступа

| Код роли | Кто | Доступ |
|----------|-----|--------|
| `guest` | Не авторизован | Только вход / регистрация / восстановление пароля |
| `user` | Авторизован, подписка неактивна | Home (ограничен), Подписка, Настройки (частично), без Connect |
| `subscriber` | Авторизован, подписка ACTIVE | Полный клиентский функционал |
| `admin` | Оператор | Admin Panel `/admin/` (отдельное веб-приложение) |
| `system` | Фоновые службы | Не UI |

### 1.4 Карта экранов клиента

```
Splash / проверка сессии
        │
        ├─ нет сессии ──► E01 Вход / Регистрация
        │                      │ успех
        └─ есть сессия ────────┤
                               ▼
                         E02 Главная (Home)
                    ┌──────────┼──────────┬────────────┐
                    ▼          ▼          ▼            ▼
              E03 Статистика  E04 Серверы  E05 Настройки  E06 Подписка
                                         │
                    ┌────────────────────┼────────────────────┐
                    ▼                    ▼                    ▼
              E07 Исключения    E08 Приложения без VPN   E09 Диагностика
                                         │
                                         ▼
                                   E10 Профиль (Should)
```

Нижняя навигация на Home: **Главная | Статистика | Серверы | Настройки**.

## 2. Общие правила UI и сообщений

### 2.1 Сообщения пользователю (Must)

- Все тексты — простой русский язык.
- **Запрещено** показывать: `401`, `500`, stack trace, JSON backend, коды исключений Go/Dart.
- Допустимо во **внутреннем** журнале диагностики (экран E09): технические метки для поддержки (`udp/443`, HTTP status как число в логе) — но не как основной Alert.

**Словарь типовых сообщений**

| Ситуация | Текст пользователю |
|----------|-------------------|
| Неверный логин/пароль | Не удалось выполнить вход. Проверьте адрес электронной почты и пароль. |
| Сервис недоступен | Сервис временно недоступен. Попробуйте ещё раз немного позже. |
| Нет интернета | Нет подключения к интернету. Проверьте сеть и повторите попытку. |
| Сессия истекла | Сеанс завершён. Войдите снова. |
| Нет подписки | Чтобы подключиться, нужна активная подписка. |
| Ошибка списка серверов | Не удалось загрузить список серверов. |
| Ошибка подключения | Не удалось установить соединение. Попробуйте ещё раз. |
| VPN permission отказ | Без разрешения на VPN ускоритель не может работать. |
| Оплата не завершена | Оплата не завершена. Если средства списаны — обновите статус через минуту. |

### 2.2 Защита от повторных нажатий (Must)

- Пока идёт сетевой запрос (вход, оплата, connect), кнопка показывает индикатор и **не** принимает повторные нажатия.
- Двойной tap по орбу Connect в течение 500 мс игнорируется.

### 2.3 Журнал и мониторинг (Must / Should)

| Событие | Журнал на устройстве (E09) | Телеметрия на сервер | Алерт ops |
|---------|----------------------------|----------------------|-----------|
| Успешный connect | Да | Да (RTT, relay, OS, version, connect_ms) | Нет |
| Ошибка connect | Да | Да (error_code без URL) | При всплеске |
| Ошибка логина | Нет (только UI) | Нет (PII) | Rate-limit на backend |
| Смена правил | Да (версия) | Нет | Нет |

Запрещено в телеметрии: URL, история сайтов, содержимое трафика, пароли, полный `connection_config`.

## 3. Сквозные сценарии (User Journeys)

### 3.1 Новый пользователь (happy path) — Must

1. Установка APK / OTA.  
2. Первый запуск → проверка сессии ≤ 2 с → E01.  
3. Регистрация → E02 (Home) с баннером «Нет активной подписки».  
4. E06 → Оплатить → браузер ЮKassa → webhook → ACTIVE.  
5. Возврат в приложение → статус подписки обновлён.  
6. Connect → системное разрешение VPN → Connecting → Connected.  
7. Пользование: зарубежные сервисы через relay; российские — напрямую / bypass.  
8. Disconnect → Idle.

### 3.2 Возвращающийся пользователь — Must

1. Запуск → silent refresh токена.  
2. Если refresh OK → E02.  
3. Если «Автоподключение» = ON и подписка ACTIVE → авто-Connect.  
4. Если refresh fail → E01 + «Сеанс завершён…».

### 3.3 Пользователь без подписки пытается Connect — Must

1. Tap орба → сообщение «Чтобы подключиться, нужна активная подписка.»  
2. Предложить перейти на E06 (кнопка / SnackBar action «Оформить»).

## 4. Экраны клиента

---

### E00. Проверка сессии (Splash)

**Назначение.** Краткий экран при старте, пока определяется: есть ли сохранённая сессия.

**Доступ.** Все при запуске приложения.

**Элементы.** Логотип StreamPass; индикатор загрузки (без текста ошибки).

**Состояния**

| Состояние | Поведение |
|-----------|-----------|
| Загрузка | Показ splash ≤ 2 с (цель ТЗ) |
| Успех (сессия жива) | → E02 |
| Успех (нет сессии) | → E01 |
| Ошибка сети при refresh | Считать «нет сессии» → E01 (не блокировать устройство бесконечным спиннером) |

---

### E01. Вход / Регистрация

**Назначение.** Авторизация или создание аккаунта. Единственная точка входа для `guest`.

**Доступ.** `guest`. Авторизованные сюда попадают только после выхода / истечения сессии.

#### 4.1.1 Элементы интерфейса

| Элемент | Тип | Текст / содержимое |
|---------|-----|------------------|
| Заголовок | Текст | StreamPass |
| Подзаголовок | Текст | Стабильный доступ к зарубежным сервисам без ручной настройки |
| Email | Поле | Подсказка: «Электронная почта» |
| Пароль | Поле | Подсказка: «Пароль»; скрытые символы; иконка показать/скрыть (**Should**) |
| Ошибка | Блок | Красный текст под формой (скрыт, если нет ошибки) |
| Primary | Кнопка | Режим входа: «Войти»; режим регистрации: «Создать аккаунт» |
| Переключатель режима | Ссылка-кнопка | «Нет аккаунта? Зарегистрироваться» / «Уже есть аккаунт? Войти» |
| Забыли пароль? | Ссылка | **Should** — экран / deep-link восстановления |
| Условия | Текст+ссылки | **Should** — «Создавая аккаунт, вы принимаете Условия и Политику» |

#### 4.1.2 Форма — валидация

**Поле «Электронная почта»**

| Параметр | Правило |
|----------|---------|
| Обязательность | Да |
| Формат | Стандартный email (`local@domain`) |
| Длина | 5–254 символа |
| Ошибки UI | «Введите адрес электронной почты.» / «Введите корректный адрес электронной почты.» |

**Поле «Пароль»**

| Параметр | Правило |
|----------|---------|
| Обязательность | Да |
| Мин. длина | 8 символов (регистрация); при входе — не пустой |
| Макс. длина | 128 |
| Допустимые символы | Любые печатные (пароль не ограничивать «только латиницей») |
| Ошибки UI | «Введите пароль.» / «Пароль должен содержать минимум 8 символов.» |

#### 4.1.3 Кнопка «Войти»

**После нажатия (по шагам):**

1. Клиентская валидация полей. При ошибке — остаёмся на E01, показываем текст поля.  
2. Блокировка кнопки + индикатор.  
3. Запрос входа на сервер.  
4. Успех → сохранить токены в защищённое хранилище → открыть E02 (замена стека, назад на E01 нельзя).  
5. Ошибка учётных данных → «Не удалось выполнить вход. Проверьте адрес электронной почты и пароль.»  
6. Нет сети / 5xx → «Сервис временно недоступен…»  
7. Разблокировка кнопки.

**Повторный быстрый tap:** игнорируется, пока идёт запрос.

#### 4.1.4 Кнопка «Создать аккаунт»

Аналогично входу, плюс:

- При конфликте email (**Should** единый текст без «email уже занят» для анти-enumeration; допустим мягкий: «Не удалось создать аккаунт. Попробуйте войти или укажите другой адрес.»).  
- После успеха — сразу E02 (подписка ещё неактивна — норма).

#### 4.1.5 Состояния экрана

| Состояние | UI |
|-----------|-----|
| Пустое | Поля пустые, ошибок нет |
| Загрузка | Spinner на primary, поля read-only |
| Ошибка | Блок ошибки + поля редактируемы |
| Нет интернета | То же сообщение «Нет подключения…» |
| Успех | Переход на E02 |

#### 4.1.6 Переходы

| Откуда | Куда |
|--------|------|
| E00, logout, session expired | E01 |
| Успех | E02 |
| Забыли пароль (Should) | E01b Восстановление |

### E02. Главная (Home)

**Назначение.** Центр управления: подключение / отключение, статус, выбранный сервер, быстрый доступ к подписке и разделам. Показывается после успешной авторизации.

**Доступ.** `user`, `subscriber`. Connect доступен только `subscriber`.

#### 4.2.1 Элементы интерфейса

| Элемент | Описание |
|---------|----------|
| Кнопка меню (≡) | Открывает E05 Настройки |
| Заголовок | «StreamPass» |
| Иконка Premium | Открывает E06 Подписка; визуально отражает активность (**Should**: корона/звезда filled если ACTIVE) |
| Статус-чип | См. таблицу состояний ниже |
| Орб Connect | Крупная кнопка-индикатор: Подключить / Отключить / Connecting |
| Подпись под орбом | Idle: краткий текст маршрутизации; Connected: длительность `ЧЧ:ММ:СС` |
| Баннер «Нет подписки» | Текст + кнопка «Оформить подписку» |
| Баннер «Нет связи с сервисом» | Текст + «Повторить» |
| Карточка сервера | Флаг региона, название региона, id relay, ping «N мс» или «—» |
| Карточка маршрута | Пояснение smart routing + переключатель «Авторежим» |
| Нижняя навигация | Главная · Статистика · Серверы · Настройки |

**Тексты статус-чипа**

| Состояние | Текст |
|-----------|-------|
| Idle | Авто-маршрут готов |
| Connecting | Подключаем… |
| Connected | Система активна |
| Error | Не удалось подключиться |
| Blocked billing | Нужна подписка |

#### 4.2.2 Орб «Подключить» (из Idle) — Must

**После нажатия:**

1. Проверить наличие интернета. Нет → Error + «Нет подключения к интернету…».  
2. Проверить авторизацию (валидный access/refresh). Нет → E01.  
3. Проверить подписку ACTIVE. Нет → сообщение + переход/CTA на E06. **Не** запускать VPN.  
4. Убедиться, что выбран/загружен relay. Нет → «Не удалось загрузить список серверов.» + «Повторить».  
5. Запросить разрешение VPN у ОС (если ещё не выдано). Отказ → «Без разрешения на VPN…».  
6. Состояние Connecting; запись в журнал диагностики.  
7. Подключиться к relay с автоматическим перебором портов (пользователь порты не выбирает): UDP 443 → 8443 → 24443 → TCP underlay 8443 → 24443.  
8. Поднять туннель, применить правила, exclusions, app bypass, split DNS.  
9. Успех ≤ 5 с (цель): Connected, показать ping, старт таймера сессии.  
10. Ошибка: Error + «Не удалось установить соединение…»; кнопка орба снова доступна для повтора. Журнал + телеметрия error_code.

**Отмена во время Connecting:** если пользователь нажал «Отключить» — прервать попытку, вернуться в Idle.

#### 4.2.3 Орб «Отключить» (из Connected) — Must

1. Остановить туннель.  
2. Сбросить таймер.  
3. Idle: «Авто-маршрут готов».  
4. Запись в журнал.

#### 4.2.4 Карточка сервера

**После нажатия:** открыть E04 Серверы.  
После возврата с выбором — обновить карточку; если уже был Connected — **Must (SaaS):** переподключиться к новому серверу с коротким Connecting.

#### 4.2.5 Переключатель «Авторежим»

| Must (целевое) | Согласовать с настройкой «Автовыбор сервера» на E05; ON = система сама выбирает лучший relay. |
| As-is риск | Локальный UI-флаг без эффекта на ядро — **недопустимо оставлять** в спецификации: при реализации Must синхронизировать с `autoSelectRelay`. |

#### 4.2.6 Баннер «Повторить»

Повтор bootstrap: config, subscription, servers. Состояние загрузки на баннере.

#### 4.2.7 Диалог обновления клиента (при старте Home)

| Тип | Условие | UI |
|-----|---------|-----|
| Мягкое | Есть `latest` новее текущей | «Доступно обновление» · Позже · Скачать |
| Жёсткое | Версия < `min_supported` | «Требуется обновление» · только Скачать / Понятно · Connect блокируется |

#### 4.2.8 Состояния экрана

| Состояние | Что видит пользователь |
|-----------|------------------------|
| Загрузка bootstrap | Орб неактивен / skeleton карточки сервера |
| Успех idle | Карточка сервера заполнена, орб готов |
| Успех connected | Таймер, ping, чип «Система активна» |
| Пустой список серверов | Error на карточке «Серверы недоступны» |
| Нет интернета | Баннер + ограничение Connect |
| Нет подписки | Баннер + Connect ведёт на оплату |

#### 4.2.9 Переходы

→ E03, E04, E05, E06; session expired → E01.

### E03. Статистика

**Назначение.** Обзор качества работы ускорителя за период (без истории сайтов).

**Доступ.** `user`, `subscriber`.

#### Must (минимальный SaaS)

| Элемент | Описание |
|---------|----------|
| Заголовок | Статистика |
| Время в сети | За сегодня / 7 дней |
| Средний отклик | мс |
| Число переподключений | число |
| Кнопка «Обновить» | Перезапрос агрегатов |
| Пустое | «Пока недостаточно данных. Подключитесь — и здесь появится статистика.» |

**Запрещено:** список посещённых сайтов, URL, содержимое DNS-запросов.

**As-is:** заглушка «Раздел в разработке» — допустима только до реализации Must; в спецификации целевое поведение — таблица выше.

### E04. Серверы / Регионы

**Назначение.** Выбор стратегии: авто, регион или конкретный сервер.

**Доступ.** `user`, `subscriber` (выбор доступен и без подписки для подготовки; Connect всё равно gated).

#### Элементы

| Элемент | Описание |
|---------|----------|
| Заголовок | Регионы |
| Pull-to-refresh | Обновить список |
| Плитка «Автовыбор» | Отмечена, если включён автовыбор |
| Группа региона | Флаг + «Amsterdam (NL)» и т.п. |
| Плитка сервера | id, «N мс» или «Недоступен», галочка выбора |

#### Действия

| Действие | Система |
|----------|---------|
| Автовыбор | Сохранить auto=true, очистить preferred server → назад на E02 → пересчитать лучший |
| Tap по региону | Предпочтительный регион, авто внутри региона → E02 |
| Tap по серверу | Фиксированный сервер, auto=false → E02; unhealthy — **Should** не выбирать, показать «Сервер временно недоступен» |
| Refresh fail | «Не удалось загрузить список серверов.» + повтор |

#### Состояния

Загрузка · Успех · Пусто («Нет доступных серверов») · Ошибка · Нет сети.

---

### E05. Настройки

**Назначение.** Управление поведением приложения и переход в маршрутизацию / поддержку / профиль.

**Доступ.** `user`, `subscriber`.

#### Секция «Подключение»

| Переключатель | ON (Must) | OFF |
|---------------|-----------|-----|
| Автозапуск | После перезагрузки устройства приложение/сервис может стартовать (Android Boot) | Только ручной запуск |
| Автоподключение | При старте с ACTIVE — инициировать Connect без нажатия орба | Только вручную |
| Автовыбор сервера | Лучший healthy relay по качеству | Учитывать выбранный регион/сервер с E04 |

Изменение сохраняется сразу (без отдельной «Сохранить»). Ошибка записи → краткий SnackBar «Не удалось сохранить настройку».

#### Секция «Маршрутизация»

| Пункт | Подпись справа | Переход |
|-------|----------------|---------|
| Исключения | «N доменов» / «Не заданы» | E07 |
| Приложения без VPN | «N приложений» | E08 |

#### Секция «Поддержка»

| Пункт | Переход |
|-------|---------|
| Диагностика | E09 |
| О приложении (**Should**) | Версия, сборка, канал обновлений |

#### Секция «Аккаунт» (**Should** / Must для SaaS)

| Пункт | Действие |

### E06. Подписка

**Назначение.** Статус тарифа, оплата, отмена, история (**Should**).

**Доступ.** `user`, `subscriber`. Экран особенно важен для `user` без ACTIVE.

#### Элементы (Must)

| Элемент | Текст / данные |
|---------|----------------|
| Заголовок | Подписка |
| Карточка статуса | «Подписка активна» / «Подписка отсутствует» |
| Срок | «Действует до ДД.ММ.ГГГГ» (если есть) |
| Primary | Нет ACTIVE: «Оплатить подписку»; есть ACTIVE: «Отменить подписку» |
| Ошибка | Блок под кнопкой |

#### Тарифы (**Should**)

| Элемент | Описание |
|---------|----------|
| Список тарифов | Месяц / Год (цена, период) |
| Выбранный тариф | Подсветка |
| Кнопка оплаты | «Перейти к оплате» |

#### Кнопка «Оплатить подписку» — Must

1. Проверка сети и авторизации.  
2. Создание платежа на сервере.  
3. Открытие страницы оплаты во внешнем браузере / Custom Tab.  
4. Пользователь оплачивает / отменяет / закрывает вкладку.  
5. При возврате в приложение — обновить статус подписки с сервера.  
6. Если ACTIVE — показать успех («Подписка оформлена») и разрешить Connect на E02.  
7. Если всё ещё неактивна — «Оплата не завершена…».

**Неуспешная оплата / отмена в платёжке:** остаёмся на E06 без ACTIVE; без обвиняющих формулировок.

**Возврат средств (**Should**):** статус через поддержку / админ; в UI — «Обратитесь в поддержку» + контакт.

#### Кнопка «Отменить подписку» — Must

1. Диалог: «Отменить автопродление? Доступ сохранится до ДД.ММ.ГГГГ.» (**Should** точная дата; минимум — подтверждение отмены).  
2. Подтверждение → запрос отмены.  
3. Успех → обновить карточку (ACTIVE до конца периода или Inactive — по политике биллинга; **целевая политика SaaS:** доступ до `active_until`).  
4. Ошибка → «Не удалось отменить подписку. Попробуйте позже.»

#### Истечение подписки — Must

- При опросе статуса: ACTIVE → Inactive.  
- Если был Connected — **Should** корректно отключить с сообщением «Срок подписки истёк».  
- Баннер на E02.

#### Продление / автопродление — Should

- Успешный webhook продления → обновить `active_until` без действий пользователя.  
- Неудачное списание → уведомить (**Should** push/email) + статус «Требуется оплата».

#### История платежей — Should

Таблица: дата, сумма, статус. Пустое: «Платежей пока нет».

### E07. Исключения (домены DIRECT)

**Назначение.** Пользовательские домены, которые всегда идут напрямую (важнее серверных правил для совпавшего шаблона).

**Доступ.** `user`, `subscriber`.

#### Элементы

| Элемент | Описание |
|---------|----------|
| Заголовок | Исключения |
| Подсказка | «Укажите домены, которые должны открываться напрямую (например банки).» |
| Поле ввода | Подсказка `*.mybank.ru` |
| Кнопка «+» / Добавить | Добавить в список |
| Список | Домен + иконка удалить |
| Пустое | «Список пуст. Добавьте домен, если сервис должен работать напрямую.» |

#### Валидация домена

| Правило | Сообщение |
|---------|-----------|
| Не пусто | «Введите домен.» |
| Допустимы `example.com`, `*.example.com` | «Введите корректный домен.» |
| Дубликат | «Такой домен уже добавлен.» |
| Макс. длина | 253 |

#### После «Добавить» / «Удалить»

1. Обновить локальный список.  
2. Синхронизировать с сервером.  
3. Если ускоритель подключён — применить правила без переустановки приложения (hot-reload).  
4. Ошибка sync → «Не удалось сохранить исключения.» + возможность повтора; локально можно оставить черновик (**Should**).

### E08. Приложения без VPN (App bypass)

**Назначение.** Исключить приложения из VPN-профиля ОС (критично для банков / Госуслуг).  
**Не путать с E07:** доменный DIRECT ≠ снятие флага VPN у приложения.

**Доступ.** `user`, `subscriber`. На не-Android — сообщение «Доступно в Android-версии».

#### Элементы

| Элемент | Описание |
|---------|----------|
| Заголовок | Приложения без VPN |
| Кнопка «Готово» | Сохранить и закрыть |
| Пояснение | «Выбранные приложения не будут использовать профиль ускорителя.» |
| Поиск | Фильтр по названию |
| Список | Чекбокс · название · package |
| Загрузка | Индикатор списка приложений |

#### После «Готово»

1. Сохранить список пакетов.  
2. SnackBar: «Чтобы применить изменения, переподключите ускоритель.»  
3. При следующем Connect — передать пакеты в VpnService.

Предустановки (банки, госуслуги, ФНС…) — включены по умолчанию (**Must**), пользователь может снять галочку.

### E09. Диагностика

**Назначение.** Статус соединения и локальный журнал для поддержки. Данные **не** уходят на сервер автоматически при «Копировать».

**Доступ.** `user`, `subscriber`.

#### Строки статуса

| Поле | Пример значения |
|------|-----------------|
| Статус | Подключено / Отключено / Ошибка |
| Сервер | Amsterdam (NL) / id |
| Отклик | 68 мс |
| Время соединения | 00:12:04 |
| Код ошибки | человекочитаемый или «—» (не raw exception) |
| Версия клиента | 0.1.1+26 |
| ОС | Android … |

#### Журнал

- Список событий connect (время, уровень, сообщение).  
- Разрешено: relay id/host/port, статус HTTP как число, `udp/443`, `tcp/8443`.  
- Запрещено: URL сайтов, пароли, полный connection_config.

#### Кнопки

| Кнопка | Поведение |
|--------|-----------|
| Обновить | Перечитать native status + log |
| Копировать | В буфер обмена; SnackBar «Скопировано» |
| Очистить | Очистить журнал (с подтверждением **Should**) |

### E10. Профиль (**Should** / Must для полноценного SaaS)

**Назначение.** Данные аккаунта и безопасность.

**Доступ.** `user`, `subscriber`.

| Элемент | Поведение |

## 5. Поведение в фоне и жизненный цикл (Must)

| Событие | Поведение системы |
|---------|-------------------|
| Сворачивание приложения | Туннель продолжает работать, если был Connected |
| Возврат в приложение | Обновить UI-статус из native; обновить подписку при необходимости |
| Блокировка экрана | Туннель работает |
| Выгрузка процесса ОС | Native VPN-сервис стремится сохранить сессию; при убийстве — Idle, журнал |
| Перезапуск устройства | Если Автозапуск ON — сервис может стартовать; если Автоподключение ON + ACTIVE — Connect |
| Потеря сети | UI Error/баннер; попытки восстановления ≤ 10 с (цель ТЗ); при восстановлении — reconnect |
| Восстановление сети | Автоповтор Connect, если пользователь не отключал вручную и политика auto это допускает |
| Обновление access-токена | Тихий refresh; при провале — E01 |
| Выход пользователя | Stop tunnel, clear tokens, E01 |
| Низкий заряд / Doze | Не обещать работу вопреки политике ОС; при обрыве — корректный Idle |

## 6. Системная логика маршрутизации (обязательное поведение продукта)

Пользователь **не** настраивает порты и протоколы.

1. Пользовательские исключения (E07) → DIRECT.  
2. Серверные Domain/CIDR rules → DIRECT / RELAY / FALLBACK.  
3. Иначе DefaultMode = DIRECT.  
4. RELAY → Hysteria2 через выбранный сервер.  
5. Android: split-tunnel для RU IPv4 + app bypass (E08) + split DNS (`.ru` отдельно от foreign DoH).

При деградации relay (**Must**): автоматически выбрать другой healthy; краткое уведомление «Переключили сервер для стабильности» (**Should** toast).

**Назначение.** Операционное управление SaaS. Отдельное веб-приложение `/admin/`.

### 7.2 Вкладка Health

| Действие | Результат |
|----------|-----------|
| Проверка | Успех: «Сервис доступен»; ошибка: понятный статус |

### 7.3 Вкладка Users

| Данные таблицы | email, статус подписки, active_until, дата создания, id |
| Обновить | Перечитать список |
| Выдать Premium (**Should**) | Меняет подписку пользователя; пользователь при следующем sync видит ACTIVE; запись в audit log |
| Забрать / бан (**Should**) | Inactive; если онлайн — при следующем sync отключение |
| Поиск (**Should**) | По email |

Уведомление пользователю на email — **Should**.

### 7.4 Вкладка Relays

| Данные | id, region, endpoint, healthy, RTT, load |
| Зарегистрировать | Форма → новый relay в БД → клиенты видят после обновления списка |
| Удалить | Подтверждение → удаление; пользователи на этом relay переключаются (auto) |
| Обновить | Актуальный health |

### 7.5 Вкладка Rules

| Редактор JSON правил | kind / pattern / mode |
| Опубликовать | Новая version; клиенты подхватывают poll’ом без переустановки |
| Ошибка JSON | «Некорректный формат правил» |

### 7.6 Вкладка Config

| Поля | min version, latest version, download URL, telemetry, интервалы опроса |
| Опубликовать | Клиенты получают при следующем `GET /config`; soft/hard update на E02 |

### 7.7 Audit / уведомления (**Should**)

Каждое опасное действие (удаление relay, бан, publish rules) → запись: кто, когда, что изменилось.

## 9. Критерии готовности спецификации (Definition of Done для документа)
