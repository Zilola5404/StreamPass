# StreamPass — Routing Policy Specification

> **Версия:** 1.0 · **Дата:** 2026-08-07 · **Статус:** Approved (Architecture)  
> **Связанные документы:** `docs/02_TZ.md` §5–7, `docs/02.2_FunctionalSpecification.md` §6, `docs/07_Architecture.md`, `docs/33_DirectVsVpnBypass.md`, `reports/Architecture/TASK-02-ArchitectureDecision.md`

Этот документ — **единственный источник истины** для политики DIRECT / RELAY / FALLBACK на клиенте.  
Разработчик **не** принимает продуктовые решения в Transport / VpnService / «по порту».

---

## 1. Цель

Российские ресурсы — **напрямую** (DIRECT / вне TUN / app-bypass).  
Зарубежные целевые сервисы — **через Relay** (Hysteria).  
Пользователь нажимает одну кнопку; порты и протоколы не выбирает.

---

## 2. Запрещённые антипаттерны (MUST NOT)

| Запрет | Почему |
|--------|--------|
| `if port == 443 && udp → DIRECT` в tunbridge / transport | Transport не знает продукт (YouTube ≠ Госуслуги) |
| `if quic → DIRECT` как постоянная политика | Обход Rule Engine; foreign QUIC снова «в лоб» к блокировкам |
| Silent «любой RELAY fail → DIRECT» без политики правила | Ломает смысл ускорителя для must-relay доменов |
| Накопление исключений в transport («ещё один UDP hack») | Rule Engine перестаёт решать |
| VpnService решает по hostname (YouTube/GitHub) | OS-слой только строит маршруты/DNS/bypass |
| Relay Manager знает домены | Он знает только RTT / alive / connect candidates |

**Временный diagnostic workaround** (локально, не в product default) допускается **только**:

- в режиме диагностики (`networkMode=tcp_only` / E09 / debug build);
- с явным логом reason;
- с записью в Known Limitations + сроком снятия;
- **не** как default `split` path.

## 3. Пять слоёв (обязательный порядок)

```
Packet (из TUN / OS)
    ↓
1. DNS Resolver          — имя ↔ IP, split DNS, cache, HostForIP
    ↓
2. Rule Engine           — сопоставление правил → режим правила (DIRECT | RELAY | FALLBACK | BLOCK*)
    ↓
3. Decision Engine       — итоговый Mode + Fallback/Health/Retry policy
    ↓
4. Route Manager         — OS routes / excludeRoute / app-bypass / DNS address на VpnService
    ↓
5. Transport Executor    — выполнить DIRECT (protect) или RELAY (Hysteria TCP/UDP)
                           без знания доменов и без смены Mode
```

\* `BLOCK` — резерв ТЗ/будущее; в MVP может не использоваться в UI.

### Ответственность слоёв

| Слой | Знает | Не знает / не делает |
|------|-------|----------------------|
| **DNS Resolver** | `.ru`→Yandex, foreign→DoH, reverse IP→host | Не выбирает RELAY/DIRECT |
| **Rule Engine** | Domain / CIDR / User exclusions → intended mode + `allow_direct_fallback` | Не dial, не QUIC hacks |
| **Decision Engine** | Итоговый Mode; health relay; применять ли FALLBACK; retry budget | Не трогает VpnService routes |
| **Route Manager** | RU CIDR exclude, intl routes, app bypass, TUN DNS=`10.10.0.1`, MTU | Не парсит YouTube/GitHub |
| **Transport** | `DialDirect` / `DialRelayTCP` / `DialRelayUDP`; errors; bytes; first_byte | **Не меняет** Mode на основе порта/протокола |
| **Relay Manager** | candidates, RTT, alive, underlay fallback (BL-017) | Домены, user rules |

## 4. Политика DIRECT

### 4.1 Всегда DIRECT (продукт)

| Класс | Примеры | Механизм |
|-------|---------|----------|
| Российские TLD / зоны | `*.ru`, `*.su`, `*.рф`, `*.gov.ru`, … | Domain rules (backend + builtin prepend) |
| Госуслуги / ФНС / банки / авиа RU | пакеты приложений | **App bypass** (`addDisallowedApplication`) — снимает VPN visibility |
| User exclusions (E07) | пользовательский список | Rule Engine, highest priority after… см. §7 |
| RFC1918 / link-local / multicast | `10/8`, `172.16/12`, `192.168/8`, `127/8`, `169.254/16` | CIDR DIRECT или never capture |
| DNS самого резолвера (bootstrap) | Yandex / DoH bootstrap IP | protect + не через relay loop |

### 4.2 OS-слой для DIRECT

- **RU IPv4:** `excludeRoute` (Android 13+) или intl-only routes (legacy) — трафик **не входит** в TUN.  
- **App bypass:** единственный способ убрать `TRANSPORT_VPN` у приложения.  
- Domain DIRECT **≠** app bypass (`docs/33_DirectVsVpnBypass.md`).

## 5. Политика RELAY

### 5.1 Всегда RELAY (продукт, must-relay)

Целевые зарубежные сервисы ускорителя. Список **ведётся в backend rules** (основной источник); builtin — safety net при sparse/offline.

Минимальный класс (не исчерпывающий):

- YouTube / Google media (`youtube.com`, `googlevideo.com`, `ytimg.com`, …)
- Instagram / Meta CDN (domain, не «весь Cloudflare /12»)
- Telegram, Discord (domain + точечные DC CIDR при необходимости)
- GitHub, LinkedIn, OpenAI/ChatGPT, Claude (domain)
- Прочие явно опубликованные RELAY rules

### 5.2 DefaultMode

**`DefaultMode = DIRECT`** (FS §6).

Обоснование: неизвестный destination не должен насильно уходить в broken/expensive RELAY; accelerator opt-in по правилам.

> Смена DefaultMode на RELAY — только через изменение FS + ADR, не «потому что в TUN уже intl».

### 5.3 Transport обязан уметь

Для Mode=RELAY:

- TCP через Hysteria с **реальным** transfer (`first_byte` / bytes > 0);
- UDP через Hysteria (включая QUIC к origin) с реальным transfer;
- Ошибки и blackhole **возвращать наверх** в Decision Engine, **не** самостоятельно переключать на DIRECT.

## 6. Политика FALLBACK

Fallback — **продуктовая политика Decision Engine**, не if в transport.

### 6.1 Поля правила (логический контракт)

Каждое правило (backend JSON / client model) логически несёт:

| Поле | Тип | Смысл |
|------|-----|-------|
| `mode` | `DIRECT` \| `RELAY` \| `FALLBACK` \| `BLOCK` | Базовый режим Rule Engine |
| `allow_direct_fallback` | bool | Если `mode=RELAY` и relay path failed: можно ли один раз DIRECT |

Сериализация MVP (без ломки API):

- `mode: "FALLBACK"` → трактовать как RELAY-first + `allow_direct_fallback=true`;
- `mode: "RELAY"` → `allow_direct_fallback=false` по умолчанию (**must-relay**);
- опционально позже явное поле в JSON rules (версия rule set+1) — отдельным API ADR.

### 6.2 Когда Decision Engine делает DIRECT после RELAY

Разрешено **только если** `allow_direct_fallback=true` (или mode=FALLBACK) **и** сработал fail-критерий:

| Fail-критерий | Определение |
|---------------|-------------|
| Dial error | `DialRelay*` вернул error |
| Blackhole | dial ok, но нет `first_byte` / bytes за **T=3s** (константа Decision, не transport policy) |
| Relay session dead | Relay Manager: not alive |

Запрещено:

- fallback «потому что UDP/443»;
- fallback для must-relay (`allow_direct_fallback=false`) — пользователю Error / retry relay / смена сервера (уже есть BL-047), **не** тихий DIRECT.

### 6.3 Примеры

| Dest | Rule | Relay broken | Итог |
|------|------|--------------|------|
| `youtube.com` | RELAY, allow_direct_fallback=false | dial/blackhole | Error / другой relay; **не** DIRECT |
| `example.org` | FALLBACK / allow_direct_fallback=true | dial/blackhole | один DIRECT + reason=`fallback_after_relay_fail` |
| `yandex.ru` | DIRECT | — | DIRECT всегда |

## 7. Приоритет правил (first match)

Строго в порядке:

1. **User exclusions** (E07) → DIRECT  
2. **Backend Domain / CIDR rules** (опубликованный rule set)  
3. **Builtin DefaultDirectRules** (RU TLD safety net) — *prepend перед backend уже сегодня; не менять смысл*  
4. **Builtin DefaultRelayRules** (узкий safety net foreign) — *append; domain-first; без Cloudflare /12*  
5. **DefaultMode = DIRECT**

Примечание по текущему коду `MergeWithDefaults`:  
`DefaultDirectRules + backend + DefaultRelayRules` совместимо с first-match, если Direct builtins идут раньше. Не переставлять без ADR.

## 8. DNS Policy (Split DNS)

| Запрос | Resolver | Зачем |
|--------|----------|-------|
| `.ru` / `.su` / `.рф` / известные RU | Yandex `77.88.8.8` (или эквивалент) | RU geo-DNS |
| Foreign | DoH (Cloudflare/др.) через protect | Стабильный foreign resolve |
| OS VPN DNS | **TUN address `10.10.0.1`** | Все queries в Go dnscache → есть hostname для Rule Engine |
| После resolve | `HostForIP` map | IP-only flows из TUN всё ещё матчят domain rules |

Запрет: весь DNS только через Cloudflare DoH (ломает RU) — см. `docs/33`.  
Запрет: OS DNS на Yandex **вместо** in-TUN, если из-за excludeRoute queries не попадают в Go (host пустой → wrong decision).

## 9. Взаимодействие компонентов

```
Flutter Connect
  → fetch rules / exclusions / bypass packages
  → VpnService (Route Manager): split routes, DNS 10.10.0.1, MTU, app bypass
  → PrepareRelay (Relay Manager) — до TUN (ADR-013)
  → StartTunnel
       → DNS Resolver отвечает UDP/53
       → на каждый flow:
            DNS/HostForIP → Rule Engine → Decision Engine → Transport.Execute(Mode)
```

### Контракт Transport API (логический)

```
Execute(mode, proto, dest) → Result{ok, err, bytes, first_byte_ms}
```

- При `mode=RELAY` transport **не** подменяет на DIRECT.  
- Decision Engine читает Result и решает FALLBACK по §6.

### Diagnostic modes (не продукт)

| Mode | Назначение | Где UI |
|------|------------|--------|
| `split` | Единственный product default | — |
| `direct_test` | force DIRECT — локализация «жив ли ISP» | E09 / debug only |
| `full_relay` | force RELAY — локализация relay path | E09 / debug only |
| `tcp_only` | drop UDP/443 — **диагностика** QUIC vs TCP | E09 / debug only |

Product release: всегда стартовать как `split`; не показывать режимы на E05 Must.

## 10. Диагностика сломанного RELAY (порядок проверки)

Симптом: «Relay connected, data не идёт; Direct Test ок».

Это **не** основание для product-правила QUIC→DIRECT. Порядок расследования:

1. **MTU** — проверить 1280 vs 1400 в diagnostic only.  
2. **protect()** — сокеты к **relay endpoint** и DoH bootstrap обязаны protect; иначе петля в TUN.  
3. **Split DNS vs route** — IP от одного path, dial другим; сверить host/ip в `[decision]`.  
4. **Policy vs Route Manager** — RU exclude не захватывает foreign; foreign в TUN.  
5. **Default route / TUN up** — routes applied, fd valid.  
6. **Blackhole metric** — `DialRelay` ok + `first_byte` timeout → баг transport/Hysteria, чинить там.
