# Аудит StreamPass перед запуском и первыми платежами

**24 ноября 2026 · `release/mvp-1` · HEAD `b433298`**

## Решение по запуску

StreamPass уже имеет основу платного продукта: Android-клиент, общий Go Core с Hysteria2, версионируемые правила, авторизацию, серверный пробный период, каталог тарифов, заказы и обработку уведомлений об оплате. **Готовность к приёму денег пока не подтверждена.** Главные препятствия — разрыв между записью успешного платежа и выдачей доступа, конфигурация Platega в стандартном деплое, защита аккаунтов и отсутствие подтверждённого сквозного прогона на одной релизной сборке.

Предлагаемый первый коммерческий этап — **закрытая платная бета на Android, один тариф Personal Basic, один платёжный путь через Platega**, как в последней релизной матрице. Предложение опирается на прежнее пожелание сначала довести Android и на более свежий сценарий Platega. Тариф и канал запуска подлежат подтверждению перед выкладкой. Windows входит в текущий RELEASE-001 и остаётся обязательным для его полной приёмки. iOS и macOS остаются требованиями исходного ТЗ для полного кроссплатформенного релиза.

## Очередь исправлений и проверок

Все строки открыты на дату аудита. Для закрытия строки записывать коммит, сборку, среду, дату и ссылку на тест или отчёт. P0 — перед приглашением платящих пользователей. P1 — перед публичным запуском в заявленном объёме. P2 — отдельное решение по объёму релиза.

### Первый пакет исправлений

- **SP-01.** Зачисление, подписка и заказ обновляются одной транзакцией. Добавлен тест PostgreSQL на откат и параллельные продления. Требуются прогон с доступным Docker и отдельная сверка исторических платежей.
- **SP-02, SP-03.** Compose передаёт настройки Platega. Канал выбирается через `BILLING_DEFAULT_PROVIDER`. Для Platega проверяются заголовки callback, привязка к провайдеру и сумма. Требуется прогон с мерчантом, подтверждение контракта, обработка отказов и сверка состояний.
- **SP-05, SP-06.** API перестал выдавать конфигурацию relay аккаунтам без доступа. Сервер перестал выдавать reset-токен в HTTP-ответе. Открыты отзыв старых relay-данных и доставка ссылки восстановления владельцу.
- **SP-15.** У формы и API USDT отключена возможность приёма оплаты. Подтверждение недоступности после выкладки и реализация проверок для будущего включения остаются открытыми.
- **SP-04 и SP-07–14.** Остаются открытыми по критериям таблицы. Контрольная оплата, приёмка на устройствах и выпуск в платную бету не проводились.

## Порядок следующей сессии

1. Начать с **SP-01**. Закрыть атомарность зачисления и тесты на частичный сбой. Одновременно можно определить точный RC и собрать исходные данные для SP-02 и SP-07.
2. Пройти SP-02–06, SP-15 и локальную интеграцию платежей. В матрице проверить отдельно отмену покупки, отсутствие webhook, задержку, дубль, оплату после окончания trial, продление активной подписки и отображение результата после перезапуска.
3. На одной сборке закрыть SP-07 и SP-08. Для оплаты использовать учётную запись и заказ, которые можно проследить от приложения до кабинета провайдера.
4. После контрольной оплаты открыть приглашения в закрытую Android-бету. Собирать количество установок, успешных Connect, начатых оплат, подтверждений и активаций. Зафиксировать первый пользовательский платёж и причину каждого разрыва в воронке.

## Ограничения проверки

- Это аудит репозитория и имеющихся отчётов. Реальная транзакция, текущее состояние production, подписи артефактов и физический прогон Android/Windows в рамках аудита не подтверждены.
- Локальный Docker Engine недоступен, поэтому тесты с PostgreSQL/Redis в контейнерах нельзя считать подтверждёнными. ADB не смог запустить сервер, подключение устройства не подтверждено.
- `go build ./...` прошёл. В `go test ./...` прошли unit-тесты биллинга и авторизации, но общий прогон завершился ошибкой локального сокета Redis и ошибкой нагрузочного сценария публичного API. Точечный повтор Redis с доступом к локальному порту прошёл. Доступность публичного API по результату нагрузочного теста не установлена.
- `go test -v ./backend/internal/integrationtest` подтвердил пропуск всех четырёх тестов из-за недоступности Docker. `go test ./...` и `go test -tags with_gvisor ./...` в `client/go_core` прошли на текущем рабочем дереве. Flutter-проверки и сборка подписанного APK в этом аудите не запускались.
